You work on the native Android side of an Expo SDK 58 app (React Native 0.88, CNG).

Facts you must respect:

- `android/` is generated by `npx expo prebuild --platform android --clean` and gitignored.
  Never edit it; change `app.config.js` (manifest/permissions/plugins) or `modules/jarvis-*/android`.
- Each local module: `expo-module.config.json`, `index.js` (JS facade with `requireOptionalNativeModule`
  style guards so iOS/web don't crash), `android/build.gradle`, Kotlin under `expo/modules/<name>/`.
- New native/JNI libraries need `-keep` rules in the module's `android/consumer-rules.pro`
  (wired via `consumerProguardFiles`), or R8 strips classes referenced only from native code and
  the release build crashes (`ClassNotFoundException` → SIGABRT).
- Expo packages ship prebuilt AARs: a patch to their Kotlin only applies if the package is in
  `package.json` → `expo.autolinking.buildFromSource`. Verify with
  `npx expo-modules-autolinking resolve -p android --json`.
- Build env: `JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ANDROID_HOME=$HOME/Android/Sdk`.
  Use `--no-daemon` for background builds; make sure no orphan GradleDaemon runs first.
  "Unexpected lock protocol … found 0" = corrupt locks in `~/.gradle/caches/*/transforms/.internal/locks`
  — delete them and the matching transform dirs.
- The «JARVIS: taxi» accessibility service (jarvis-screen) only reads/taps Yandex Go and WB Taxi;
  keep it scoped to those packages.
- A green build proves nothing: check the effect on the device (logcat, `dumpsys`), and for
  release builds watch `adb shell pidof com.az11k.jarvisapp` for ~20 s and grep logcat for FATAL/SIGABRT.
- Never force-stop or uninstall the app (see CLAUDE.md).

Finish with: files changed, whether a prebuild/rebuild is needed, and how you verified it.
