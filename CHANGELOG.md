## [Unreleased]

### Added

- Hands-free mode: wake word «Джарвис» / "Jarvis", automatic end-of-speech detection, replies only to phrases that start with the wake word, tap-to-interrupt
- On-device voice activity detection over the raw microphone stream (adaptive noise floor, pre-roll)
- OpenAI Responses API with function calling and built-in web search, replacing text-command parsing
- Neural JARVIS voice: on-device Piper voices (Ruslan for Russian, Alan for English) with sentence-by-sentence playback; falls back to the device voice while a model is downloading and on iOS
- Arc-reactor HUD with conversation transcript; voice and mic settings persist between launches
- `open_url` action; reminders are read aloud by JARVIS when they fire
- `list_reminders` and `cancel_reminder` tools: ask JARVIS which reminders are set, cancel one or move it to another time
- Vision: `analyze_image` tool — JARVIS opens an in-app scanner (`expo-camera`) that shoots by itself after focusing — back or selfie camera — or picks from the gallery, sends the photo to a vision model and reports what it sees, reads or translates text (`EXPO_PUBLIC_OPENAI_VISION_MODEL` overrides the model)
- Telegram as the user's own account on Android (local module `modules/jarvis-telegram`, TDLib, `EXPO_PUBLIC_TG_API_ID`/`EXPO_PUBLIC_TG_API_HASH`): log in from the ✈️ Telegram window (phone, code, two-step password), with the session database encrypted by an Android Keystore key. By voice: list unread chats, read and summarize a chat, mark it read, search messages by word and sender, send and reply, compose a reply on request, delete your own last messages for everyone, and have new messages from watched chats, mentions and (optionally) private chats read out as they arrive. Messages are sent as soon as the user asks; deleting is read back and runs only when the user's next phrase confirms, enforced in code
- Background listening on Android: a microphone foreground service (local module `modules/jarvis-background`) keeps the wake word working with the app in the background or the screen off, with a "Turn off" action in its notification
- Uzum Tezkor food delivery (`src/services/tezkor.js`, unofficial API of uzumtezkor.uz): by voice, search restaurants and shops for a dish, cuisine, product or place near a saved delivery address (`tezkor_search_food`); list what is open now, optionally by kitchen (`tezkor_restaurants`); read a restaurant's menu (`tezkor_menu`); set and remember the delivery address (`tezkor_set_address`); and open Uzum Tezkor in the Uzum app to place the order (`open_tezkor`). Open places are listed first with rating, delivery time and price in sum. Placing the order is done by the user in the app

### Fixed

- Fallback replies (task too complex, missing OpenAI key, connection problem) were always in Russian; they now follow the language the user spoke
- The wake word did nothing on iOS: the on-device recognizer only exists on Android, so standby phrases were silently dropped. iOS now looks for the wake word in the OpenAI transcript; on Android the standby hint says to tap the core until the on-device model has downloaded
- Returning to the app in the middle of a turn (e.g. from the camera) reset JARVIS to standby while it was still thinking
- Repository names with dashes were mangled (markdown stripping removed `-`)
- Selected voice was overwritten on every reply

### Changed

- The interface is now English only: status lines, buttons, the log, the voice picker, the Telegram login window, error messages and notifications were partly in Russian. JARVIS still understands and answers in Russian or English
- Privacy: in standby the wake word is checked on the device, and only phrases that start with it are sent to OpenAI — background speech (TV, calls, conversations) stays on the phone; a bare «Джарвис» is acknowledged without a cloud round-trip
- Speech recognition now uses OpenAI `gpt-transcribe` (`EXPO_PUBLIC_OPENAI_TRANSCRIBE_MODEL` overrides it) for better accuracy; the on-device recognizer is the offline fallback when OpenAI is unreachable or takes longer than 8 s
- Conversation mode: after an answer JARVIS keeps listening for 10 s (15 s if it asked a question) without the wake word; speaking keeps the conversation going, silence, a sign-off («отбой», «спасибо, всё») or opening another app returns it to standby
- Upgraded Expo SDK 54 → 58 (React Native 0.88, React 19.3) and all Expo modules
- Splash screen is now configured via the `expo-splash-screen` config plugin
- Switched to Continuous Native Generation: `android/` and `ios/` are generated by `expo prebuild` and no longer committed
- Updated deprecated APIs (`expo-image-picker` media types, `expo-audio` permissions)
- Fixed React Compiler lint errors (refs read during render)

### Removed

- `open_camera` tool: it opened the system camera app and overlapped with the vision scanner, so «открой камеру» could launch the camera app instead of `analyze_image`
- Biometric lock screen on launch (`expo-local-authentication`): it only ran on a cold start and didn't cover the wake word, which works with the screen off
- GitHub voice commands (create or delete a repository, read recent commits) and the `EXPO_PUBLIC_GITHUB_TOKEN_KEY` setting; no GitHub token is bundled into the app anymore
- Unused dependencies: `openai`, `axios`, `expo-av`, `expo-camera`, `expo-file-system`, `expo-status-bar`, `react-native-tts`, `@react-native-voice/voice`, `react-native-background-actions`, `react-native-markdown-display`, `@react-native-community/cli`, `expo-blur`, `expo-local-authentication`
- Obsolete config: `newArchEnabled`, `edgeToEdgeEnabled` (now always on), manual `appComponentFactory` manifest override

## [1.0.0] - 2025-07-16

### Added

- 🗣️ Voice Input (STT: Speech to Text)  
  Users can now speak directly with J.A.R.V.I.S.

- 🤖 GPT-4 Powered Responses  
  Smart conversational replies generated by OpenAI

- 🧠 Contextual Memory (AsyncStorage)  
  J.A.R.V.I.S. remembers key actions and recent input during a session

- 🚀 App Launching via Voice  
  Opens apps like Telegram, YouTube, etc., based on spoken commands

- 🧠 Smart Commands via OpenAI (Search & Generation)
  - "Find a guitar lesson on YouTube" → opens relevant YouTube search
  - "Create a login page in React" → generates React login page code
